# One-pager ingredients — Pull the Source
Raw material for the team's own one-pager. Every number below is in `results/eval_scores.json`.

## Question
When a source behind an AI recommendation is withdrawn, does the model revise the recommendation exactly when the remaining valid evidence no longer supports it? And does an explicit dependency table help?

## Method (short)
- 12 fictional consumer-purchase scenarios (synthetic). Each: 3 requirements, 6 numbered sources, labels Supported / Contradicted / Insufficient evidence.
- One recorded initial decision, then three independent branches from that same exchange:
  1. essential source withdrawn → should become Insufficient evidence
  2. irrelevant source withdrawn → should stay Supported
  3. one of two independent supports withdrawn → should stay Supported
- Branches 2 and 3 penalise a model that just abstains after any withdrawal (always-abstain = 12/36).
- Two prompt conditions with identical rules and evidence: A ordinary; B must write and update a requirement-to-source dependency table.
- Claude Haiku, 96 separate fresh-context calls, one sample per cell. Dataset, keys, prompts and scorer frozen (hashed) before evaluation. Deterministic scoring, no model judge.

## Verified findings
| | A: ordinary | B: dependency table |
|---|---|---|
| Initial decision correct | 12/12 | 12/12 |
| Essential withdrawn → correctly revised | 12/12 | 12/12 |
| Unsupported retention after essential withdrawal | 0/12 | 0/12 |
| Unnecessary withdrawal after irrelevant removal | 0/12 | 0/12 |
| Correct retention with redundant support | 12/12 | 11/12 |
| Overall post-update accuracy | 36/36 | 35/36 |

- Reference policies (computed, not model runs): always-abstain 12/36; always-Supported 24/36.
- Paired by scenario: both conditions fully correct on 11; A only 1; B only 0; exact sign test p = 1.0.
- Headline: **null result at ceiling.** The model already propagated withdrawals correctly on these explicit cases; the dependency table had nothing to fix.
- The one miss (E12, B): after "rated 1200 W on its highest setting" was withdrawn, the model would not accept "1180 W on high" as proof of the maximum draw and abstained. Scored wrong under the frozen key; the item wording is arguably ambiguous.
- Exploratory: the model named only one of the two redundant supports in 10/12 initial replies per condition; when we withdrew the one it had named (8/12 scenarios), it switched to the other and stayed Supported in 8/8 (A) and 7/8 (B). It never cited the lure or the irrelevant source (0/12 each).

## References
1. Yang & Jia (2025), When Do LLMs Admit Their Mistakes? arXiv:2505.16170 — retraction of the model's own errors, mechanistic.
2. Sadhu, Shahad & Marino (2026), DeReLab, arXiv:2608.30413 — large generative benchmark for defeasible belief updating; reports confirmation bias. Strong overlap in question.
3. PALIMPSEST, github.com/chleiva/palimpsest (working paper, not peer reviewed) — truth-maintenance store that propagates withdrawals; closest overlap in semantics.

## Limitations (say these out loud)
- Synthetic, 12 items, one hidden structure, written and keyed by an AI assistant, not second-reviewed; one ambiguous item.
- Ceiling effect: cannot distinguish the conditions.
- One model, one sample per cell, uncontrolled default settings, exact model ID unknown.
- Calls ran inside an agent harness, branches replayed as transcripts; 11/96 calls had a stray unrelated tool call.
- The prompt states the decision rule; real settings do not.
- Not evidence that models handle retractions well in general.

## Do not claim
"First", "novel", "solves", "models are robust to retraction", or any percentage without its count.
